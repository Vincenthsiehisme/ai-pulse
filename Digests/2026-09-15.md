# 訓練與推論同時鬆綁專屬 GPU 叢集

> 今天的問題：訓練與推論不靠緊密耦合的專屬 GPU 叢集之後，各自拿什麼撐住？

Hugging Face 在部落格發表技術文章，說明如何在 HF Jobs 上以非同步方式執行帶 LoRA 的 GRPO 訓練。協調不靠 NCCL，改用一個儲存 bucket 加一個 proxy 串接各個獨立的 job。

GRPO 是強化學習微調常見的訓練方法，傳統做法仰賴 NCCL 做多機多卡的同步梯度通訊，通常需要租用緊密耦合的專屬 GPU 叢集才跑得動。

Perplexity 的本機 agent Portable Computer 正式在 Windows 上線，是其雲端 agent 產品 Perplexity Computer 的本機版本，靠 NVIDIA RTX GPU 加速跑本機模型，讓多步驟任務的規劃與執行留在裝置端。

Perplexity Computer 原本是雲端執行的 agent，負責規劃並執行多步驟任務，運算成本與硬體規模都綁在 Perplexity 自己的伺服器上。

把這兩則放在一起看，訓練端與推論端在同一天各自鬆開了對緊密耦合專屬叢集的依賴。Hugging Face 讓 RL 微調可以拆成一般排程 job 去跑，Perplexity 讓 agent 的規劃與執行搬到消費級顯卡上執行，方向像是同一條供應鏈的兩端同時鬆綁。
