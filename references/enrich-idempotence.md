# 潤稿的冪等靠誰守 —— 2026-08-12 那晚重寫了昨天的文章

> 消費者：`scripts/pulse-enrich-apply.py` 的 `overwrite_verdict()` 與 `--force`，
> `scripts/selftest.py` 的五條判準，`scripts/enrich-runbook.md` 的自動化模式。
> 規格先於實作（紅線 9）：這一頁先寫，碼才動。

## 發生了什麼

`enrich-runbook.md` 說這條鏈是冪等的：

> prep 只挑「還有待編輯佔位」的 Event；apply 寫完後佔位消失、`enriched: true`，
> 下次 prep 自動跳過。所以重跑不會重潤已潤的，成本只跟「新事件數」走。

2026-08-13 對著 git 歷史查，這句話在 08-12 那晚不成立：

```
_probe/enrich-worklist.json 最後一次內容變動
  2026-08-11T19:12:40Z   a54723e  nightly: enrich + narrative 2026-08-11

08-12 那班（9096e2b，19:16:19Z）改了哪些事件的 prose
  08-11 清單 11 則裡的 10 則，一則不差
```

也就是說 08-12 那班**沒有重跑 `pulse-enrich-prep.py`**，它拿倉庫裡那份 08-11
留下的清單又潤了一次。三個後果，沒有一個會讓任何東西變紅：

1. 昨天已經潤好的又被重寫。比對 `evt-2026-08-11-5bb657`（Testing ads in ChatGPT）
   前後兩版，講的是同一件事，只是換句話說。**文章內容每晚無故漂移。**
2. 當天的新事件一則都沒潤。08-12 進來的 7 則從頭到尾沒被碰過。
3. 清單卡死。推進清單的那一步就是沒跑的那一步，所以它自己不會恢復。

而那顆 commit 動了 18 個檔、訊息寫著 `nightly: enrich + narrative 2026-08-12`。
**它看起來是健康的一晚。**

## 為什麼冪等會消失

因為執行冪等的不是 apply，是 prep：

```
prep   決定「誰該被潤」——用佔位詞篩，這是冪等的來源
apply  拿到什麼寫什麼，並無條件 fm["enriched"] = True
```

`apply` 在此之前**沒有任何守衛**。跳過 prep，冪等就整個不見了，
而 apply 不會有半句話。

這是這個 repo 反覆出現的形態的又一例：**一個不變式的執行點，掛在另一步有沒有被叫到上。**
上游那一步是由一份給模型讀的 runbook 指揮的，而 runbook 是文件不是碼。

## 修法：把守衛放在寫入那一刻

`overwrite_verdict(fm, body, force)` —— body 裡沒有佔位詞就拒絕寫入，
除非明寫 `--force`。

判準用**佔位詞**不用 `enriched` 旗標，理由是佔位詞是 body 的實際狀態，
而 `enriched` 是一格可以被寫錯的 frontmatter。2026-08-10 那次事故
（段落標題重複導致 `thin_fact`）就是 `enriched: true` 但內容其實壞掉——
以旗標為準的話，那批永遠救不回來。以佔位詞為準，至少判準讀的是真的東西。

拒絕是**逐則**的，不是整批中止：合法的那幾則照寫，被拒的印出來，最後回離開碼 1。
runbook 的失敗處理是「任一步非預期失敗就停、不要 push 半成品」，非零會讓那條鏈停下。

## `--force` 存在的理由，以及它不該被寫進 runbook

有真的需要重寫已潤稿事件的時候：2026-08-10 那次要修 13 則被段落標題洗成空的事實層。
那是人在追一個已知故障，知道自己在覆蓋什麼。

所以逃生口要留，但**不能出現在自動化模式那一節**。一旦 runbook 寫了
「拒寫的話加 `--force` 再跑一次」，這道守衛就等於不存在——半夜那一端會照做，
而它正是最沒有能力判斷「這次覆寫是對的嗎」的那一端。

selftest 有一條釘住這件事：`enrich-runbook.md` 的自動化模式那一節不准出現 `--force`。

## 這道守衛擋不住什麼

擋得住「拿過期清單重潤」，擋不住「prep 沒跑、而今天剛好沒有新事件」——
那種情況下 apply 收到空的結果、什麼都不做、回 0，跟正常的安靜夜晚一模一樣。

真正要分開那兩件事，得讓 worklist 自己帶一個產生時間，apply 檢查它是不是這一輪產的。
那是下一步，記在 BACKLOG。這裡寫出來，是為了不讓這道守衛被當成「這條鏈已經安全了」。
