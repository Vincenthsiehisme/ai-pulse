# 抓取禮貌：不要長期用高於一天一班的頻率打人家的站

> 消費者：`scripts/lib/politeness.py`（門檻與判準）、`scripts/lib/clock.py` 的
> `runs_per_day()`、`scripts/selftest.py` 的四條判準。
> 規格先於實作（紅線 9）：這一頁先寫，判準才進碼。

## 這條規則在守什麼

我們抓的每一個站都是別人的。這條鏈的預設頻率是**一天一班**，而且 robots.txt
每條來源最多七天重驗一次。兩個數字都不是效能取捨，是禮貌——**429 是唯一一種
「錯在我們自己」的狀態碼**（`data-refresh.yml` 那個死人開關步驟的原話）。

兩個門檻：

```
每日班的次數    ≤ 1        寫 _corpus/ 的那條鏈
robots 重驗間隔  ≥ 7 天     兩處 --stale-days 必須同值
```

「兩處同值」本身就是判準的一部分。`data-refresh.yml` 裡 `--stale-days` 出現兩次
（`Robots recheck` 那一步跟最後的死人開關那一步），不同值代表同一份 robots.txt
在同一班裡被用兩種節奏對待——那是設定漂移，不是取捨。

## 為什麼今天才把它寫成判準

2026-07-25~27 曾把 cron 臨時調快成 `0 */2 * * *`（一天 12 班），`--stale-days`
從 7 調成 1。收班是靠一個**單次觸發的排程任務**，而那個安排本身就是這個 repo
一直在修的那種「警報自己把自己關掉」。

所以又補了一個**每週的 Cowork 排程任務**去看它有沒有收乾淨。那支任務有兩個問題：

1. 它需要推 main 才能自動收班，而它沒有平台注入的 repo 授權——於是
   **prompt 裡被塞了一個明文 PAT**，躺了 35 天（2026-07-26 → 08-30）。
   一個為了守「禮貌」而存在的檢查，代價是一個長期外洩的憑證。
2. 它一週跑一次。**偵測延遲最多 7 天**——七天用 12 倍頻率打人家的站。

兩個問題都因為同一件事：這是一條**設定檔常數的判準**，卻被做成了一個需要
憑證與 LLM 的排程任務。它該住在 selftest 裡，那裡每次 push 都跑、零憑證、
零 LLM，而且**改壞的當下就紅**，不是七天後。

## 已經有的那一半，跟它刻意留下的洞

`lib/clock.py` 已經在管 cron：

```
cron_unannotated   每一行 cron 都要在同一行註解寫出台北時間
misanchored_daily  每天一班的 cron 必須跑在 16:00Z
```

但 `misanchored_daily` 抓不到加密期，**而且是刻意的**。它靠
`daily_utc_hour()`，那支的 docstring 自己寫著：

> `0 16 * * *` → 16。`0 */2 * * *`（一天 12 班）、`0 16 * * 1`（每週）都回 None
> ——**前者是暫時加密期**，後者是週班，兩種都不該被這條規則管。

週班那一半是對的：把 `0 3 * * 1` 逼成 16:00Z 沒有意義。
但「暫時加密期」那一半是**在加密期間寫下的豁免，然後留了下來**。

於是今天的狀態是：`0 */2 * * *` 這個形狀——正是禮貌檢查唯一要抓的那一個——
是既有規則**寫明放行**的那一個。規則不是漏掉它，是替它開了門。

這一頁補的就是那道門。

## 為什麼判準放 `lib/` 不放 selftest 的斷言裡

同 `lib/inventory.py` 的理由：**沒有任何測試抓得到一條把自己改成恆真的測試**
（M350 教的）。`acase(A, B)` 被改成 `acase(B, B)` 是全綠的；判準搬進 lib 之後，
同一個改動變成「lib 回了錯的東西」，當場紅。

`runs_per_day()` 放 `clock.py` 而不放 `politeness.py`，是為了**不要寫第二份
cron 解析**。`daily_utc_hour()` 已經在那裡拆五個欄位了，再寫一份的話兩份會在
某個邊角上分岔，而分岔的那天不會有東西紅——那是這個 repo 的頭號病。
`politeness.py` 只放**政策**（門檻是多少、什麼算問題），不放解析。

## 這一版明確**不**管什麼

- **不管每條來源自己的 `frequency` 欄位。** 那是 `sources.yaml` 的事，
  而那一層今天沒有人在守。寫下來，不假裝有蓋到。
- **不管實際發出的請求數。** 判準讀的是設定檔，不是流量。設定對而
  程式多打了幾次，這條抓不到。
- **不管 429 有沒有真的發生。** 那要接來源健康那一層，是另一輪的題目。

## 這條落地之後，那支週排程任務可以退役

它做的三件量測（cron、兩處 `--stale-days`、過期註解）前兩件由 selftest 接手，
而且更早、更便宜、更嚴。第三件（過期註解）是文件債，不值得為它養一個
需要憑證的排程任務。

**退役之前先確認 selftest 這幾條真的會紅**——`scripts/mutate.py` 的
M354–M357 就是幹這個的。清單記著它們會被殺；哪天不被殺了，代表這道門又開了。
