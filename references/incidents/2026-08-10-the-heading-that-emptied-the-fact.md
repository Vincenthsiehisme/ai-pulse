# 2026-08-10 — 一行重複的標題，讓站上六天沒有新文章

## 一句話

潤稿端把段落標題寫進了值裡，`pulse-enrich-apply.py` 又加了一次自己的標題，
於是 `pulse-gate` 抽「事實」那一段時抽到 **0 字**，`thin_fact` 把每一則都擋下。
**13 則裡 13 則中，零例外**，而四個警報全綠。

## 現象

`published` 停在 73，最後一則上線 2026-08-07，最後一則的事件日期是 08-04。
8/5 之後產生的事件全部躺在 `review`：08-05(1)、08-06(4)、08-07(2)、08-08(1)、08-10(5)。

漏斗上斷得非常乾淨：

```
           語料      事件     上線
08-03      425  →     5   →    5
08-04      445  →     9   →    9
08-05      425  →     1   →    0   ← 斷點
08-10      465  →     5   →    0
```

## 機制

1. `scripts/enrich-runbook.md` 的結構化 schema 範例，把標題寫進了**值**裡：
   `"fact": "## 事實：發生了什麼，具體、只講證據有的"`。
2. 潤稿端照著填，`enrich-result.json` 的 `fact` 以 `## 事實` 開頭。
3. `pulse-enrich-apply.py` 重組 body 時再加一次自己的標題，寫出：

   ```
   ## 事實
   ## 事實
   NVIDIA 官方部落格報導，…
   ```

4. `pulse-gate.section(body, "事實")` 取「這個標題到下一個 `##` 之間」，
   而下一個 `##` 正好是那個重複的標題 → **0 字**。
5. `0 < readiness.thin_fact_min_chars (20)` → blocker `thin_fact` → 不上線。

實測對照：`evt-2026-08-08-46b340` 的事實 section 是 **0 字**；
人工潤稿、值裡沒寫標題的 `evt-2026-08-04-e23cff` 是 **110 字**，順利上線。

## 為什麼不會自癒

`pulse-enrich-prep.py` 只挑「body 還留著待編輯佔位」的事件。這 13 則的
`enriched` 已經是 `true`、佔位詞也被覆蓋掉了——**下一班 prep 不會再挑它們**。
潤稿端永遠不會回頭修，gate 永遠擋著。沒有人手動介入的話，它們會一直躺在 review。

## 為什麼四個警報都沒叫

| 警報 | 當時 | 為什麼漏掉 |
|---|---|---|
| `--alert-stale` | 綠 | 抓取正常，語料每天四百多筆進來 |
| `--alert-unenriched-days` | 綠 | 這 13 則**是**已潤稿的，`未 enrich = 0` |
| `--alert-enrich-stale` | 綠 | 潤稿鏈每天都推回 main |
| `--alert-coverage` | 綠 | 必盯公司都有來源在看 |

四個判準量的都是「**有沒有在動**」，沒有一個量「**有沒有東西出去**」。
一條每個零件都在轉、輸出是零的產線，在這套監看下是全綠的。

`pulse-monitor` 其實算得出來——`待處理=16`、`待處理最久=18 天` 就印在畫面上，
只是**沒有任何旗標吃這兩個數字**。同一個形狀這個 repo 修過好幾次
（`scoring.value` 算了沒人讀、判斷層帳本寫了沒人讀），這次輪到產出量。
補這一格的警報列為下一輪，規格要先寫：08-01、08-02 兩天真的是 0 則上線
而且合理，所以判準不能是「今天沒上線就叫」，得是「有事件卡著**且**連續 N 天沒上線」。

## 修法

**碼（這個 PR）**

- `pulse-enrich-apply.py` 新增 `strip_own_heading()`：寫回之前剝掉值開頭那一行
  自己的段落標題。**這一層不信任輸入的形狀**——寫進檔案的形狀由碼決定。
  兩種寫法都剝：整行只有標題，或標題後接冒號再接內容（後者只剝前綴）。
- `enrich-runbook.md` 的 schema 範例改成純內文，並寫明「值裡不要寫標題」。

修在 apply 而不是只修 runbook，是因為 runbook 是一份給人／模型讀的文件，
而 apply 是確定性那一層。**只修文件等於把正確性押在下一個讀者身上。**

**資料（另一顆直推 main 的 commit）**

確定性地刪掉那 13 則重複的標題行，重跑 `pulse-gate` + `pulse-dashboard` + `pulse-render`。
