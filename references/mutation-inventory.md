# 變異盤點：測試自己有沒有在守東西

> 這份文件是**規格**，`scripts/mutations.yaml`（清單）與 `scripts/mutate.py`（跑法）
> 是它的實作。三者不一致時以本檔為準，**先改本檔再改碼**（紅線 9）。

## 為什麼要有這一層

`health-alarms.md` 講的是「警報自己把自己關掉」。這一份講的是再上面一層：
**測試自己有沒有在守東西**。

2026-07-26 當天 selftest 是 224 條。224 是一個很好看的數字，而它回答不了唯一重要的
那個問題：**把碼改壞，會不會有東西紅？** 同日實測，把 `pulse-monitor.py` 的 `main()`
結尾 `return rc` 改成 `return 0`——整條鏈紅不紅就靠這個數字——selftest **224/224
全過**。224 條測試，一條都沒動。

（「幾條」這個數字本身不必再追。它會隨著補測試一直長，而它長多少跟守不守得住
沒有關係——那正是這一節在講的事。要看守不守得住，跑 `python3 scripts/mutate.py`。）

這是同一個病的第五個實例：**用「測試有幾條」代理「壞掉會不會被抓到」**。
兩者在正常路徑上正相關，所以平常看不出來；分岔的那天，正好就是碼被改壞的那天。

量「壞掉會不會被抓到」只有一個誠實的方法：**真的把碼改壞，看有沒有紅**。

## 為什麼不能用手做

2026-07-26 之前做過一輪手工的：一條一條 `sed` 進去、跑 selftest、看幾條紅、再還原。
結論是「94 個注入點裡 47 個存活」。那句話寫進 BACKLOG 的當天就開始腐爛——它是
**174 條測試**時量的，一週後 selftest 長到 224 條，那個比例已經沒有任何意義，
但它還印在清單上，看起來像個現況。

手工盤點的產物是**一個數字**；數字會過期，而過期不會讓任何東西變紅。
可重跑的產物是**一個判準**；判準會自己更新。

手工那輪還踩到兩個坑，兩個都必須寫進工具裡，否則工具會重蹈覆轍：

### 坑一：針腳不唯一，會假裝成「存活」

needle `'        if r.get("unenriched_undated"):'` 在 `pulse-monitor.py` 裡命中兩處
（console print 區塊與 `[alert]` 區塊都是 8 格縮排）。`str.replace(a, b, 1)` 改到了
前者，於是 alert 那條路徑根本沒被動過，selftest 全綠——差一點就得出「這個釘子
不存在」的結論，然後去補一條早就存在的測試。

規則：**注入前先 `assert 出現次數 == 1`**。次數不是 1 的條目一律判為
**stale（清單過期）**，不是「通過」。stale 要跟 survivor 一樣讓工具回非零——
一份自己悄悄跳過條目的清單，就是一顆永遠綠的燈。

### 坑二：改壞語法不算變異

一個讓 `render()` 直接 raise 的改動會讓 selftest 紅，但那紅的是崩潰、不是斷言。
把它算成「殺掉了」，等於用「碼能不能跑」代理「碼對不對」——又一個比事實寬鬆的
代理指標。

判準是 selftest 的最後一行：selftest 是一支平鋪的腳本，任何未捕捉的例外都會讓它
**印不出 `N/M passed`**。所以：

| selftest 輸出 | 判定 |
|---|---|
| 有 `N/M passed`，且 fails > 0 | **killed**（測試抓到了） |
| 有 `N/M passed`，且 fails = 0 | **survived**（沒有任何測試在守這裡） |
| 沒有那一行 | **crashed**（這個變異無效，不算數，要換一個） |

crashed 跟 stale 一樣要回非零：它代表清單裡有一個條目已經不是有效的變異了。

實例（2026-07-26）：M13 原本寫的是「在既有事件那一支再蓋一次 `ingested_at`」，
注入後縮排對不上，selftest 印不出結尾那行。**那是改壞語法，不是變異。**
若沒有這條判準，它會被記成「殺掉了」，而那一格其實從來沒被測過。改寫成一個
同樣痛、但語法合法的單行替換之後，它是真的被殺。

### 坑三：一條「每次注入都會紅」的檢查，會把 kill 訊號變成常數

下一節那條「每個 `find` 在目標檔案裡剛好出現一次」的檢查，第一次接上去就出事了：
mutate.py 跑到某一條時，那一條的針腳**正被它自己換掉**，於是這條檢查必紅。
結果是**每一條變異都「被殺」**——包含四條早就知道守不住的（M01/M02/M03/M11），
全部被誤判成 killed。

一個對所有輸入都給同一個答案的訊號，資訊量是零。這跟 `return 0` 的 CI、跟
`survives: true` 填滿的清單是同一件事，只是這次它長在量測工具自己身上。

規則：注入期間，mutate.py 用環境變數 `MUTATE_IN_FLIGHT=<id>` 告訴 selftest
「這一條的針腳現在本來就不該在」，selftest 只跳過**那一個 id**，其餘十九條照數。
基準線那一輪不設這個值。CI 也不設——只有 mutate.py 設它，而且一次一個。
selftest 另有一條釘住「`MUTATE_IN_FLIGHT` 只認得清單裡的 id」，免得打錯字就
等於憑空關掉一條檢查。

## 清單記的是「量到的事實」，不是「希望的樣子」

每個條目都帶一個 `survives:` 欄位，記的是**上次實測的結果**。工具在**兩個方向**
都比對：

- 記 `survives: false`，實際存活 → **回歸**。有測試被刪掉、或碼被改得繞過了測試。
- 記 `survives: true`，實際被殺 → **記錄過期**。有人補了測試但沒更新清單。

只釘一個方向的話，把 `survives: true` 全部填上去就會永遠綠——那是把清單變成一份
許願單。理由跟覆蓋率那一節、跟 exit code 那一節一樣：**一個天天紅的 CI 跟一個
永遠綠的 CI 一樣沒有資訊**，而一份永遠對的清單什麼都沒說。

`survives: true` 的條目**必須**寫 `why`，講清楚為什麼現在守不住、以及誰在管
（通常是 BACKLOG 的某一條）。已知的缺口掛在那裡是誠實（紅線 8）；沒有理由的
`survives: true` 是掩蓋。

## 不准弄髒工作區

工具會真的改原始碼檔案。三道護欄：

1. **開跑前**：目標檔案在 `git status --porcelain` 裡有任何改動就拒跑。
   已經髒的樹出事時分不清哪些改動是誰的。
2. **每一輪**：原文存在記憶體，還原走 `try/finally`，Ctrl-C 也還得回來。
3. **收工後**：逐檔比對 sha256 與開跑前一致，不一致就大聲叫並回非零。
   還原失敗而沒人知道，就是把變異過的碼 commit 上去。

工具**不做** git 操作、不 commit、不 push。它只讀寫那幾個目標檔案。

## 這一層不保證什麼

- **不保證測試是對的。** 一條斷言了恆真條件的測試也會讓變異變紅。
  變異測試量的是「有沒有東西在守」，不是「守的東西對不對」。
- **不保證覆蓋完整。** 清單是人挑的，挑漏了不會有人知道。它回答的是
  「我列出來的這些地方守不守得住」，不是「所有地方」。所以條目要挑
  **壞掉最痛的**那些，不是最好寫的那些。
- **不取代 selftest。** selftest 每次 push 都跑、0.5 秒；變異盤點跑 N 次 selftest，
  是分開的一條工作流。selftest 只快速檢查清單的針腳還在不在（見下）。

## selftest 這邊只做一件事：快速抓清單過期

`scripts/mutate.py` 要跑幾十次 selftest，太慢，不適合掛在每次 push 上。但
「清單過期」這件事不需要跑變異就查得到——只要數一下每個 `find` 在目標檔案裡出現
幾次。所以 selftest 釘的是：

- `mutations.yaml` 讀得進來，`id` 不重複，必填欄位都在。
- **每個 `find` 在它的目標檔案裡剛好出現一次**（注入期間略過 `MUTATE_IN_FLIGHT`
  指到的那一個，理由見坑三）。
- 每個 `survives: true` 的條目都有 `why`。

這樣改碼的人在 0.5 秒內就會知道清單需要跟著改，不必等到週一那班。

## 第二輪（2026-07-26 稍晚，`fix/heat-claims-a-measurement`）

25 條：21 被殺、4 存活。存活的還是 M01 / M02 / M03 / M11，還是 BACKLOG P1，
一條都沒變——這一輪沒有補到任何新洞，因為新增的五條（M21–M25）是**跟著修法

新增的五條守同一件事：`heat` 在沒有任何傳播證據時不准長出數字。分五條不是為了
湊數，是因為「走回去」有五個互不相干的入口——源頭重新計算（M21）、門禁不擋
（M22）、`value` 悄悄改權重（M23）、前台把 `None` 印成 0（M24）、送 0 給敘述層
（M25）。堵住其中一個不等於堵住，而且後三個從後端看起來都還是誠實的：
`heat` 欄位是 `null`，只有畫面上或 LLM 收到的那份是謊。

這一輪也證了盤點清單的第二個用途：它是**修法有幾個出口**的檢查表。寫 M21 的
時候只想到源頭，是列到第三條才發現 `value` 的權重是一個獨立的說謊路徑。
