# 敘述層：唯一讓 LLM 寫字的地方，以及它不准說什麼

> 這份文件是**規格**，`scripts/lib/narrative_guard.py`（判準）、
> `scripts/pulse-narrative-apply.py`（執法點）與 `_config/narratives.yaml`（產物）
> 是它的實作。三者不一致時以本檔為準，**先改本檔再改碼**（紅線 9）。

## 為什麼這一層需要一份自己的規格

紅線 1 說 runtime 迴圈 0 LLM。這句話很容易被讀成「這個 repo 裡沒有 LLM 寫的字」，
而那是假的：`_config/narratives.yaml` 的 `now` / `next` 就是 LLM 每夜寫的。

紅線 1 真正說的是**判斷**不由 LLM 決定——發不發、算幾分、擋不擋，全部是規則。
敘述是另一回事：那六段主線描述是要給人讀的，模板拼不出人話。

所以這裡有一個很窄但很真實的入口：**整條鏈唯一由 LLM 產生、而且會被 commit
進 repo 的文字**。窄不代表無害。一段沒人檢查的散文可以把一個不存在的量測
講成論據，而且讀起來完全正常——因為散文本來就不附出處。

## 誰寫哪一格

| 欄位 | 誰寫 | 夜間鏈會不會動它 |
|---|---|---|
| `thesis` | 人 | 不會 |
| `now` / `next` | LLM（`pulse-narrative-prep` 出題 → `pulse-narrative-apply` 寫回） | **會**，該主線有新事件時重寫 |
| `lenses[].question / answer / watch` | 人 | **永遠不會** |

最後一列是這份文件存在的直接原因，下一節就是。

## 2026-07-26 的實例：堵住上游只擋得住新的謊

`heat` 這個欄位長期印出一個沒量過的數字（來龍去脈見
`references/gate-config-status.md`）。修法有五個出口，其中一個是
`pulse-narrative-prep.py`：heat 是 `None` 時送「未量測」給 LLM，不送 0——
送 0 的話 LLM 會寫出「熱度低、還沒共振」這種拿沒量過的東西當論據的句子。
那條修法當天就補上了，selftest 也釘住了。

然後 `_config/narratives.yaml` 裡的這兩句原封不動地留著：

```
infra-cost   → lenses[投資人].answer：四則皆單源、heat 偏低（8–14），還沒跨來源共振。
product-market → lenses[投資人].answer：目前只有官方發布、無採用數字，heat 8–10 偏低。
```

兩句都在 `lenses`。而 `lenses` 是上表裡**夜間鏈永遠不會重寫**的那一格。
上游堵住的是「以後不要再寫出這種句子」；已經寫出來的那兩句，沒有任何一班會經過
它們。它們會一直掛在站上，直到有人剛好讀到。

這就是同一個病的又一個實例：**用「入口已經修好」代理「站上沒有假話」**。
兩者在正常路徑上一致，分岔的地方正好是那些不再被任何流程碰到的角落——
而不再被碰到，正是它們最需要被檢查的理由。

## 規則：量化熱度宣稱

**vault 裡沒有任何一則 Event 的 `heat` 是數字時，敘述層不准出現量化的熱度宣稱。**

判準（`narrative_guard.find_heat_claims`）：文字裡出現 `heat`（不分大小寫）或
`熱度`，其後 12 個字元內出現數字，且該段窗口內沒有否定詞
（`未量測` / `量不到` / `沒量到` / `未接線`）。

- 「heat 偏低（8–14）」→ 命中。
- 「heat 8–10 偏低」→ 命中。
- 「傳播熱度未量測，12 則全部單源」→ 不命中（窗口內有否定詞）。
- 「12 則單源」→ 不命中（沒有提到熱度）。

窗口取 12 個字元、否定詞開豁免，兩者都是為了讓規則擋住**病徵**而不是擋住
**寫法**。一條會誤傷誠實句子的檢查，會被下一個人用改寫繞過去，那時它就變成
一顆永遠綠的燈——跟它想擋的東西是同一個病。

### 命中之後做什麼

`pulse-narrative-apply.py`：**拒收那一個欄位**，該主線的其他欄位與其他主線照常
寫入，印 `[reject]` 並回非零。

不自動改寫。`voice_clean` 那一層可以機械替換，是因為「網絡→網路」不改變句子
主張；把一句事實宣稱改寫掉，等於這支腳本自己編了一句話出來——確定性的腳本
不該有意見。拒收是把事情交回人，而非零 exit code 是讓那一班紅。

`selftest.py`：直接掃 `_config/narratives.yaml` 全檔，**包含 `thesis` 與
`lenses`**。apply 只看得到當班寫入的東西；已經躺在檔案裡的句子要靠這條。
上一節那兩句就是躺著的那種。

### heat 真的量到之後

四項傳播輸入接上線之後（BACKLOG 的社群線 M3），vault 會出現數字 heat，
這條檢查就自動放行。放行之後它驗的是「vault 裡存在量到的 heat」，
**不是「敘述層引用的那個數字是對的」**。下一節。

## 這一層不保證什麼

- **不保證敘述是對的。** 它擋的是一種特定的謊（把沒量過的熱度講成量過的），
  不是一般的事實查核。散文有一百種說錯話的方法，這裡只釘住走過一次的那一種。
- **不保證繞不過去。** 「熱度未量測，不過大概是 8」在窗口裡有否定詞，會過。
  規則擋的是無意間的重述，不是刻意的規避——刻意規避要靠 review。
- **不驗證數字本身。** 見上一節：heat 可量測之後，這條只確認「有東西可引用」。
  要驗到「引用的是那一則的那個數字」，得先讓敘述層帶出處，那是另一件事。
- **不管 `thesis` 與 `lenses` 的其他內容。** 那兩格是人寫的，這裡只掃同一條
  熱度規則；其餘靠 PR review（`CONTRIBUTING.md`）。
